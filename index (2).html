About this project

AI-Driven Machine Learning for Spatio-Temporal Earnings Prediction, Demand Forecasting & Intelligent Optimization of Multi-Platform Gig Delivery Partners.

Dataset

Prediction problem

The dataset carries no single obvious label column, so the target was chosen by scanning for the numeric field most people using a dataset like this would actually want to forecast before starting a trip: Earning_per_hour. Columns computed after a trip finishes (gross/net earning, fuel cost, incentive amount, the dataset's own pre-computed "Predicted" and "Recommended platform" fields) were excluded from the model inputs, since a driver deciding whether to accept a job doesn't have those numbers yet — using them would leak the answer.

This is a regression problem. A ridge-regularised multiple linear regression is trained entirely client-side (closed-form normal equations, no server) on standardised numeric features plus one-hot-encoded platform, service category and weather.

The three pieces of the project title

  • Spatio-temporal earnings prediction — the Prediction tab estimates ₹/hour from trip conditions that vary in space (Area, Zone Factor) and time (hour, day type, time period).
  • Demand forecasting — the Dashboard's Area × Time-period heatmap shows where and when demand actually runs highest, from real Demand_Score averages, not a projection into future dates the data doesn't contain.
  • Intelligent optimization — the Prediction tab's "Platform optimization" table re-scores the exact same trip through the model once per platform and ranks the result, so you can see which platform the model expects to pay best for those specific conditions.

Recommended KPIs & charts

  • Total trips, average earning/hour, average net earning, average demand score, average distance, and share of high-earning trips as headline KPIs.
  • Earning per hour by platform and by time period, to compare which platform and shift actually pays best.
  • Distance vs. earning per hour, to see how trip length erodes hourly pay.
  • Service-category mix and platform trip-count, for volume context behind the averages.
  • Area × time-period demand heatmap, for the spatio-temporal view named in the project title.

Limitations — read before trusting a number

  • The model is a single linear regression trained in-browser on whichever file is currently loaded — it is illustrative, not a production forecasting system.
  • Accuracy, R², RMSE and MAE shown in Model Performance are calculated live from this dataset's actual train/test split; nothing is invented, but they will shift on every reload or re-upload because the random train/test split changes.
  • "Demand forecasting" here means summarising demand patterns already present in the historical data (by area and time period) — it is not a time-series model projecting demand into future dates, since the dataset has no continuous daily time series to fit one on.
  • "Platform optimization" ranks platforms using the same single regression model with the platform indicator swapped — it assumes the other trip conditions would be identical across platforms, which may not hold in practice.
  • Correlation in this dataset does not establish real-world causation between conditions and pay.
  • Re-uploading a spreadsheet with different columns will break feature matching unless it uses the same column names as the original dataset.
